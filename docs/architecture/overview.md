# 架构概览

## 当前形态

当前版本由产品交互原型和本地 WebRTC 会议实验组成。产品数据仍为演示数据；本地
会议实验会调用浏览器真实媒体设备，并允许同源的两个浏览器窗口建立点对点连接。
它不接入真实用户、课程、服务端信令、媒体服务器或云端录制服务；当前页面只提供本地 MediaRecorder 实验。

## 组件

| 组件 | 职责 | 拥有的数据或行为 | 允许依赖 |
| --- | --- | --- | --- |
| 首页与会议大厅 | 会议发现、快速创建、预约和加入 | 当前页面、会议入口状态 | 前端状态与演示数据 |
| 创建会议面板 | 选择会议/课堂模式和课程班级 | 创建表单与邀请范围；模式切换保留自定义主题 | 演示课程数据 |
| 会中控制台 | 视频宫格、主持控制和会议信息 | 音视频开关、布局、计时、本地录制 | 前端状态与本地 MediaRecorder |
| 成员与聊天侧栏 | 按会议模式展示成员范围、状态和即时讨论 | 面板选择、消息列表 | 课程使用演示名单；普通会议使用本地 WebRTC 窗口状态 |
| 教学互动 | 签到、投票、测验和随机选人 | 活动选择与发布状态 | 演示活动数据 |
| 课后报告 | 汇总出勤、互动、录制和待办 | 报告维度切换；本地会话使用当前快照并按会议号恢复本机录制 | 演示报告数据、前端状态与本机录制存储 |
| 回放管理 | 搜索、查看、分享和标记回放状态 | 当前页面选中回放与本机存储的本地发布标记 | 演示回放数据与前端状态 |
| 会议资料 | 按目录查看、搜索、上传、移除和预览资料 | 当前页面资料列表、筛选和预览状态；本机保存上传元数据与可恢复的文件内容 | 前端状态、本地文件内容、localStorage 元数据与 IndexedDB 文件内容 |
| 本地 WebRTC 内核 | 设备采集、双窗口信令和点对点媒体 | 本地媒体流、连接状态 | 浏览器媒体与 WebRTC API |
| WebRTC 自动化测试环境 | 在进程内模拟媒体设备、BroadcastChannel 和 RTCPeerConnection | 可控轨道、信令频道、连接状态 | Vitest、jsdom、Testing Library |

## 关键流程

1. 用户从大厅选择快速会议、预约会议或加入会议。
2. 课堂模式关联课程和班级，形成默认参会名单。
3. 用户进入会中控制台，使用会议控制和教学互动。
4. 结束会议后进入课后报告，查看出勤与互动结果。

当前本地会话报告的聊天数量只统计进入会议后产生的本地和同源远端消息；会中显示的
初始聊天内容仅用于原型界面展示，不计入本次会话快照。会话新增消息计数最多为
100,000 条，超过后保持上限；可见聊天历史仍只保留最近 200 条。历史会议报告仍使用演示统计。
聊天频道只用于同源本地实验，不提供身份认证或访问控制；接收端要求消息为聊天对象、
文本非空且不超过 2000 个字符，发送者名称超过 80 个字符或类型异常时使用远端参会者
占位名。发送端同样拒绝超过 2000 个字符的消息，避免异常窗口或输入污染本地消息列表；
可见聊天历史最多保留最近 200 条，会话新增消息计数仍独立累计。
普通会议会沿用通用会议文案并隐藏课堂互动入口；加入会议号时因本地房间号不携带课程
元数据，按普通会议处理。课程课堂才显示课堂互动和课堂报告语义。
成员面板中的课堂麦克风控制使用同步引用维护最新状态，连续快速操作不会因 React 批量更新
读取旧闭包而丢失最后一次切换；“全体静音”会同时更新该引用和界面状态。
普通会议的成员范围严格限制为当前页面本地窗口和同源远端窗口：未开启设备时仍保留
一个本地窗口占位，收到远端媒体流后再增加一个远端窗口；该面板只读，不提供课程名单、
出勤统计或全体静音操作。课程课堂继续使用演示班级名单和主持控制。
已结束会议从“我的会议”打开报告时沿用会议记录中的模式：历史课程报告可以展示演示
课程统计，历史普通会议报告只展示通用参会、会议互动和会议资料语义，不回退为课堂报告。
报告导出同样必须使用报告模式：课程报告导出课程统计，普通会议导出通用参会和会议消息
摘要，当前本地会话优先导出页面内快照，并在有课堂活动时写入具体已发布活动名称；导出
结果是本地 Blob 文件，不代表服务端报告。
报告、回放和会议邀请分享使用当前应用根页面的 `?share=report|replay|meeting` 查询参数，而不是伪造的
服务端资源路径；应用首次读取后会消费分享相关参数，避免用户返回首页或刷新时旧目标再次自动打开，
同时保留其他非分享查询参数。会议邀请引用同时携带经过校验的本地房间号和会议模式，打开后只预填加入
弹窗，不自动请求媒体权限或加入会议；历史回放按本地演示目录定位；当前报告会将经过校验的会话快照放入
本地引用，打开后可以恢复本地摘要。报告快照只接受整数统计、0–2 个本地窗口和不重复的
已知活动 ID；非法快照回退到对应模式的演示报告。引用只在当前前端原型内可识别，不创建服务端权限、
报告文件或媒体资源；缺少或无效的快照会回退到对应模式的演示报告。报告快照的本地会话时长最多 7 天，聊天消息计数最多 100,000；超出边界按无效快照处理，避免分享引用制造异常统计。报告分享引用中的快照原始字符串在 `JSON.parse` 前最多允许 100,000 个字符，超过时直接使用对应模式的演示报告。回放本地发布标记仅保存
当前设备上的已知演示标题，读取时同时限制存储原始字符串和去除首尾空白后的标题长度；存储不可用、超限或标题未知时按未发布处理。
回放管理页和课后报告页的查看区域都支持显式关闭按钮与 Escape 关闭，关闭只清理当前页面的查看状态，
不会改变本地发布标记或报告快照。
全局搜索使用静态演示索引，并按会议 ID合并当前本机预约和本机创建会议历史；会议中心和全局搜索
同时把会议号作为可检索字段；本机会议结果会
标记为本机数据并统一导航到“我的会议”，点击回放或资料结果会打开对应的前端演示查看器/详情，
已在目标页面时也会更新选中条目；它不声称覆盖服务端数据。搜索定位已结束的本机会议时会同步
选中“已结束”列表，避免定位后落入空的即将开始列表。
会议结果同时携带房间号作为稳定定位键；同名本机历史与静态日程并存时，不会仅凭标题误选状态分组。
全局搜索、通知浮层、个人菜单和会议行操作菜单是互斥的临时上下文；搜索和通知触发按钮通过 `aria-expanded`、`aria-controls` 和 `aria-haspopup="dialog"` 暴露当前状态，对应工具面板使用非模态 `dialog` 角色并关联可读标题；个人菜单和会议行菜单触发器通过 `aria-expanded`、`aria-controls` 和 `aria-haspopup="menu"` 关联菜单区域。个人菜单、会议行菜单和会中设置菜单打开后将焦点移到首个可用菜单项，菜单项支持 ArrowUp/ArrowDown、Home/End 循环导航；Escape 仍关闭菜单并恢复触发按钮焦点。切换到全局工具浮层时会取消个人菜单的旧焦点恢复动作，避免新工具上下文被个人按钮抢回。会中会议侧栏使用 `tablist`、`tab` 和 `tabpanel` 关系暴露当前成员、聊天或课堂互动视图，标签采用 roving tabindex，并支持左右/上下方向键及 Home/End 在标签间循环切换。面板、个人菜单、会议行菜单、会中设置菜单、会议侧栏、回放查看区、资料详情和资料预览主动关闭后恢复原触发按钮焦点，侧栏切换标签后按当前标签恢复焦点；资料预览关闭后仍保留资料详情，第二次关闭才退出详情。切换到个人菜单或主导航时会取消旧面板的焦点恢复目标。主导航切换页面时会清理全局搜索或通知浮层，以及回放、资料和会议结果的旧定位状态，避免临时上下文残留到新页面。
会议结果会把目标条目带入“我的会议”视图；如果该会议只存在于首页日程索引，也会在会议中心补出
对应的本地演示条目，并按房间号去重。
回放生成通知携带当前演示目录中的回放标题，点击后复用同一目标定位流程；通知已读 ID 按已知通知白名单保存
在本机，写入后回读校验，其他同源窗口通过 `storage` 事件同步角标和列表；没有明确资产目标的通知
仍只导航到对应页面。
回放的“本地已发布”标记只在本机存储写入成功后更新；写入失败会保留未发布状态并提示重试。
同源其他窗口对该标记的新增、更新或清除会通过 `storage` 事件同步到当前页面。
已结束且报告快照标记有录制的本机创建会议和预约会议会进入回放管理页；回放引用携带
经过校验的会议号作为稳定定位键。回放页优先使用当前页面内存中的 Blob，缺失时按会议号
从 IndexedDB 尝试恢复；本地会议历史和预约状态恢复完成前不会执行录制孤儿清理，避免刷新
期间用空列表误删可恢复媒体。媒体不存在时只展示会议元数据和恢复提示，不伪造播放器或下载文件。
如果会议历史或预约的 `localStorage` 不可读，也会跳过录制清理，而不是把未知归属的媒体当作孤儿删除。
新建本机预约会生成避开静态日程的独立数字房间号，并随预约记录保存；旧记录缺少房间号时仍使用兼容默认值。
预约记录结束会议后会保存 `past` 状态、报告快照和报告生成状态，会议中心不再把已结束预约放回
即将开始列表；旧预约记录缺少结束态时按 `upcoming` 兼容处理。

会议入口媒体偏好只对主动加入当前会议生效；首页课堂、日程、本机预约和创建会议等直接进入入口会重置为默认开启，避免上一场加入操作污染下一场会议。
会中计时从本地 WebRTC 进入 `starting`/`waiting`/`connecting`/`connected` 状态后开始；仅打开会议大厅、主动离会或连接失败不会继续累计，报告快照使用该页面会话计时。
会中标题会把本地 WebRTC 阶段映射为“大厅”“正在入会”“等待参会者”“连接中”“进行中”或“连接异常”；主动离会回到“大厅”，会中左上角返回按钮还会同步切换到会议首页并清理搜索定位状态。会中更多设置菜单以及成员、聊天、课堂互动侧栏可由按钮切换，并由全局 Escape 关闭。该标题只描述当前页面的本地连接状态，不代表服务端会议状态。
移动端会中保留共享屏幕、录制、成员、聊天、课堂互动和布局切换等核心入口；打开会议侧栏时视频区与侧栏改为上下布局，避免 340px 固定侧栏造成横向溢出；当底部空间不足时，仅中央控制组横向滚动，结束会议按钮保持固定可达。顶部会议标题和会议号允许省略，不得挤压设置操作。报告页在窄屏将摘要头部改为纵向布局，报告操作独占可用行；会议资料和课堂回放的顶部搜索/上传操作会换行并在工具区内收缩，保持主要入口可达。
首页课堂入口固定使用课堂演示房间号；其他日程和预约入口使用各自记录的房间号，避免直接进入路径复用上一场本机会议身份。
快速会议创建时会生成避开静态日程、当前本机预约和已保存本机历史的 9 位数字房间号；预约会议同样避开本机历史；主动加入会议则使用用户输入并经过校验的房间号。会议号必须为 6–18 位数字，输入中的空格或短横线会先归一化，其他字符直接拒绝；创建主题最多 120 个字符，入会名称最多 80 个字符；会议大厅的聊天频道也只为该范围内的规范化房间号创建。每次 WebRTC 入会都会轮换 peer 标识，避免离会重入时复用旧信令身份；peer 标识、本机房间候选和本地资料标识优先使用 `crypto.randomUUID`，缺少或调用失败时降级到 Web Crypto 随机值或本地时间/随机组合；这些标识只用于本地路由或页面状态，不承担鉴权。
会议中心默认展示首页当前课堂，并按房间号与搜索补入条目去重；已结束列表、当天会议摘要和
本周完成数量继续按房间号去重，并把已知静态历史房间号纳入本机覆盖判断，避免同一房间的本机历史/预约来源重复展示或重复计数；“今天的会议”
摘要从去重后的即将开始和已结束条目中统计日期标记为今天的会议，避免会议结束后从当天摘要消失。
会议资料的详情和预览共享同一当前资料上下文；切换资料会清理旧预览，Escape 按预览优先、详情其次的顺序关闭，关闭详情也会清理预览，避免展示内容与当前资料不一致。当前页上传只接收非空且原始长度不超过 160 个字符的文件名；图片、视频和音频使用当前页面生成的对象 URL 进行真实预览，文件内容在当前单页应用会话内保留并允许下载原文件，支持 IndexedDB 的浏览器会在刷新后按资料 ID 恢复文件内容，不支持或持久化失败时只恢复元数据并提示重新上传，不读取或伪造云端内容。上传资料的元数据由本机存储保存，文件内容由 IndexedDB 尽力保存，使资料页和全局搜索使用同一份本地资料索引；资料搜索结果携带稳定资料 ID，导航到资料搜索结果时优先按 ID 恢复对应详情，文件名仅作为兼容回退，因此同名资料不会误选，刷新后仍可恢复已保存元数据。存储载荷、条数、字段和重复标识均受边界校验，写入后会回读验证，资料元数据删除或跨窗口同步时会清理内存与 IndexedDB 中不再对应的文件内容。该状态不代表云端同步，清除站点数据后恢复默认演示目录。
会中录制使用本地 `MediaRecorder` 从当前窗口的本地媒体流生成 WebM Blob；共享屏幕期间录制源使用屏幕视频加本地音频，停止共享后恢复摄像头视频。报告回放区域可在当前页面预览并下载，结束会议或组件卸载时停止录制并释放录制器。录制 Blob 以会议号为键尽力保存到 IndexedDB，历史报告打开时只恢复同会议号的本机录制，异步恢复使用操作序号防止旧报告串入当前报告；不支持 IndexedDB 或存储失败时仍可在当前会话使用，但重新打开历史报告不会伪造可下载文件。静态历史报告的录制字段仍可能只是演示状态。
快速会议会写入本机创建会议记录，结束后转入已结束列表；记录会沿用创建时的课堂/普通会议模式，课堂记录保存课程、班级和课堂类型元数据，普通会议保存本机演示说明；记录最多保留 20 条并校验房间号、状态和会话报告快照，历史条目仍只代表本机演示数据。历史写回会先合并最新存储中不同房间的记录，再按当前操作覆盖同房间记录；写入成功后当前页面重新读取合并结果，降低同源窗口并发写入造成的丢记录风险。
本机存储写入失败时，快速会议仍允许进入当前会话，但会明确提示历史未保存；结束会议或手动生成历史报告时，页面状态仍可继续使用并提示持久化失败，刷新后的恢复能力不作保证。预约、会议历史和回放发布状态的写入必须在 `setItem` 后回读并比对内容；取消预约必须在 `removeItem` 后确认键已不存在。存储 API 不抛异常但静默丢弃变更时，页面按失败处理，不反馈已保存或已取消。

本机会议行的删除是显式的数据管理操作：只对本机创建记录和本机预约记录显示，静态演示条目保持只读；删除和取消预约前使用页面内可访问确认框，删除确认后先验证会议元数据从 `localStorage` 移除，再清理同会议号的 IndexedDB 录制和报告待办键，并分别反馈附属清理失败。删除失败时不从 React 列表确认移除会议记录，避免把未落盘状态误报为已删除；确认框支持 Escape、Tab 焦点循环和关闭后的原触发按钮焦点恢复。
本机存储读取也有载荷边界：预约记录超过 100,000 个字符、会议历史超过 1,000,000 个字符或回放标记超过 512 个字符时按对应本地数据不可恢复处理，避免异常同源数据在初始化阶段被无界解析。恢复本机历史和预约时，房间号必须为 6–18 位数字，主题必须非空且不超过 120 个字符（原始值和去除首尾空白后的值都受限）；会议 ID、日期标记、时间、详情、类型和视觉标记也必须为非空且不超过各自展示边界，历史会先过滤无效记录并按房间号去重，再最多恢复 20 条，避免异常前缀遮蔽后续合法会议；恢复对象及其中的报告快照按支持字段白名单归一化，未知字段不会进入页面状态或后续写回，与创建和加入入口保持一致；超长或异常记录按无效本地数据忽略，只有完全缺少房间号的旧预约才兼容默认房间号。分享报告或回放引用的主题同样限制原始值长度，报告快照中的参与者名称遵守相同边界，避免空白填充绕过校验。创建会议主题限制为 120 个字符，超限时保留创建面板并提示用户。
当前页面会监听本机预约和本机会议历史的 `storage` 事件；同源其他窗口新增、更新、删除或清空这些记录后，会重新读取并校验对应数据。当前窗口自身的操作仍直接更新 React 状态，不依赖该事件。
聊天频道切换或离开会议时，旧频道的排队消息必须通过频道实例校验丢弃，不能混入重入后的新会话历史或计数；聊天消息及发送者名称在规范化前也受原始长度限制，避免首尾空白绕过 2,000/80 字符边界。
会议中心的本周完成数量会在静态演示基数上叠加本机已结束创建会议和已结束预约，保持摘要与本地历史列表一致；累计会议时长也会在静态 12.6 小时基数上叠加有有效报告快照的本机历史时长，并按房间号去重，缺少快照的旧记录不伪造时长。
本机报告待办按会议号使用独立的 `localStorage` 键保存；报告页监听该键的同源 `storage` 事件，其他窗口新增任务或切换完成状态时，当前页面会按默认任务与已保存任务重新合并，避免报告视图停留在旧快照。清空本机存储时也会重新应用默认任务，但不会把静态演示报告写入本机。
本机会议记录同时保存报告是否已生成；关闭自动生成时，历史报告保持“等待生成”状态，手动生成
后再写回本机记录，刷新页面不会把报告状态恢复成默认值。旧记录缺少该字段时从已有的自动报告
选项推导；旧本机历史缺少 `mode` 字段时从 `type` 兼容推断普通会议或课堂。恢复快照时以会议记录自身的模式为准，
模式冲突的快照按无本地快照处理并回退到该模式的演示报告；历史报告打开时使用记录自身的房间号
上下文更新状态，避免刷新后误更新默认房间的记录。

## 本地 WebRTC 实验

- `getUserMedia` 负责摄像头和麦克风采集。
- `BroadcastChannel` 在同源浏览器窗口之间交换 offer、answer 和 ICE candidate。
- 当前会话收到的信令按队列串行处理，并按 SDP 描述去重 offer/answer，避免并行回调在同一
  `RTCPeerConnection` 上重复推进协商状态。
- 信令接收会限制来源/目标标识、SDP、ICE candidate、SDP mid 和 username fragment 的
  长度，并要求 ICE 行索引为非负整数；超出边界或类型异常的消息会在交给 WebRTC 前丢弃。
  远端描述到达前的 ICE 会记录发送方，只在对应对端的描述建立后刷新，且暂存队列最多保留
  128 条，超过时丢弃最早候选，避免旧对端或异常信令造成状态污染和无界积累。
- `RTCPeerConnection` 负责点对点音视频传输。
- `getDisplayMedia` 与 `replaceTrack` 负责屏幕共享和恢复摄像头。
- 入会前可同时关闭音频和视频；此时使用空本地媒体流加入，不调用 `getUserMedia`，也不伪造媒体轨道。只有用户选择开启音频或视频时，媒体采集 API 才是入会前置能力。
- 如果用户在等待对方加入时已开始屏幕共享，后续创建 peer 会直接发送当前屏幕轨道；摄像头轨道不会重复发送，停止共享后仍恢复当前摄像头轨道。
- 屏幕共享期间切换摄像头只更新本地待恢复轨道，不替换正在发送的屏幕轨道；摄像头轨道已结束时不能伪造恢复成功。
- 摄像头或麦克风切换完成时必须读取最新的本地开关状态；切换请求等待期间用户的最后一次静音或视频操作优先，并同步到替代轨道的 `enabled`。
- 设备切换或屏幕共享产生的异步媒体请求如果已被新请求、离会或重新加入取代，返回的替代轨道必须停止；如果过期请求已经换过发送器，则先恢复当前仍有效的轨道；若 `replaceTrack` 已经改变发送器后才报告失败，也必须回滚发送器，避免继续引用随后停止的轨道；过期失败也不能覆盖当前会话错误状态。
- 设备枚举请求按最新请求生效；旧加入流程或旧 `devicechange` 返回的设备列表不能覆盖当前会话的设备选择。
- 没有 live 视频轨道时不允许开始屏幕共享；无视频入会仍可加入和聊天，但需重新加入并开启摄像头才能共享。无媒体入会不会通过设备切换器临时添加轨道，页面只保留离开连接操作。
- 远端正常离会时清理旧 peer、远端身份和待处理 ICE 候选，重新加入必须从干净连接状态开始。
- 页面离开时通过 `pagehide` 复用离会清理并通知同源对端；进入 BFCache 时不误发离会。
- 信令协商异常时清理当前 peer、信令频道、媒体轨道和待处理 ICE；清理后返回的旧异步异常必须忽略，用户可主动重新加入。
- 信令协商异常在清理前会向当前对端发送 `leave`，让双方回到各自的错误或等待状态，避免一端残留连接中状态。
- 对等连接的连接状态和 ICE 回调必须同时校验会话代次与当前 peer；离会重入后，旧连接的异步回调不得改写新会话状态或向旧信令频道发送候选。
- 房间号只隔离本机同源频道，不是服务端房间，也不具备访问控制能力。

## 自动化测试边界

- 测试脚本用确定性的模拟实现替代真实媒体设备、窗口频道和点对点连接，因此可在无
  摄像头、无麦克风、无图形浏览器的环境中运行。
- 自动化测试验证应用自身的房间隔离、协商状态、轨道控制与资源清理逻辑，不等价于
  浏览器 WebRTC 实现兼容性、真实硬件质量或跨网络连通性测试。
- 所有 Web 改动的统一检查入口是 `web/package.json` 中的 `check` 脚本。

## 系统不变量

- 课程、班级和成员身份由学习通统一身份体系提供，不在会议系统重复维护。
- 教学互动产生的成绩必须保留活动来源和人工确认能力。
- 未经授权的参会者不能看到课程名单、成绩或受限资料。
- 原型数据与生产数据必须有清晰边界。
- 本地连接进入 `disconnected` 或 `failed` 后必须释放旧对等连接和信令状态，进入可重新加入的错误状态；不能复用已失效的 peer。

## 后续生产架构边界

跨设备版本需要独立的会议编排服务、实时信令、STUN/TURN、媒体转发服务、录制转码、消息服务、
课堂活动适配层和会后分析流水线；前端不能直接依赖媒体基础设施或持有长期凭据。
