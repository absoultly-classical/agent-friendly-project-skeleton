# TASK-ID：简短的任务标题

- 状态：待开始
- 负责人：未分配
- 创建日期：YYYY-MM-DD
- 更新日期：YYYY-MM-DD
- 关联需求：REQ-NNN
- 关联决策：ADR-NNNN 或无

## 目标

写一个可观察的结果，并用一两句话说明它为什么重要。

## 范围

### 包含

- 明确要交付的内容。

### 不包含

- 与本任务相邻但不能被自行推断为任务范围的工作。

## 必读上下文

- 只链接完成当前任务需要的权威文档、代码入口和依赖信息。
- 不要写“参考之前的聊天”。

## 约束与假设

- 已确认事实标记为“约束”，不确定判断标记为“假设”。
- 每项未确认假设都要有验证方法。

## 计划

- [ ] 一个小而可验证的步骤。
- [ ] 验证结果并更新受影响文档。

## 验收标准

- [ ] 可观察的行为或交付物符合预期。
- [ ] 相关验证通过。
- [ ] 受影响的长期文档已更新。

## 工作记录

用简短的带日期条目记录重要发现、决定和方向变化，不必罗列每一个普通操作。

## 验证证据

| 验证内容 | 方式 | 结果 | 日期 |
| --- | --- | --- | --- |
| 需要证明的行为 | 自动化测试、人工检查或评审 | 通过或失败，以及关键细节 | YYYY-MM-DD |

## 交接

- 当前状态：哪些已经可用，哪些尚未完成，改动是否已提交。
- 改动范围：准确的文件路径或足够小的目录范围。
- 风险与未决问题：不确定事项、影响和需要谁确认。
- 下一步：另一位 Agent 可以立即开始的一项具体操作。
