# 0062：完善全局搜索与通知入口

## 目标

将工作台顶栏中目前只显示 Toast 的搜索、通知入口，补成可继续操作的本地演示交互，减少用户点击后的断层。

## 范围

- 搜索会议、课堂回放和会议资料，并按结果跳转到对应页面。
- 展开通知列表，显示未读数量，支持单条通知进入对应页面和全部标记已读。
- 在首页和“我的会议”/“课堂回放”/“会议资料”顶栏保持一致的工具入口。
- 不接入服务端搜索、推送、账号或持久化通知。

## 验收标准

- [x] 点击搜索后可见搜索输入框，输入关键词会显示匹配的会议、回放或资料。
- [x] 点击搜索结果会关闭浮层并进入对应产品页面。
- [x] 点击通知后可见通知列表和未读数量；单条通知可定位到对应页面。
- [x] “全部已读”会清除未读数量和红点，并给出反馈。
- [x] 搜索和通知浮层支持 Escape 关闭，不影响既有会议、回放、资料和 WebRTC 流程。
- [x] 补充 jsdom 自动化测试，并通过 test、typecheck、lint、build。

## 验证记录

2026-08-29：完成全局工具浮层、搜索结果导航、通知已读状态和 Escape 关闭；`npm run check` 通过（2 个测试文件、85 项测试，typecheck 和 build 通过），`npm run lint` 通过，`git diff --check` 通过（仅有换行符提示）。

## 风险与边界

搜索与通知数据均为页面内演示数据，刷新后恢复默认；跳转只改变当前本地单页应用的视图，不代表已接入真实服务端能力。
