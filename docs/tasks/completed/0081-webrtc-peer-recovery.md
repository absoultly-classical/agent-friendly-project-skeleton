## 目标

修正本地 WebRTC 对等连接在 `disconnected` 或 `failed` 后只显示等待、却继续复用失效 peer 和旧信令状态的问题，让用户能够明确看到断开并重新加入。

## 完成内容

- 连接异常时通知当前远端并关闭旧 `RTCPeerConnection`。
- 清理远端 peer ID、offer 目标、待处理 ICE 候选和旧 BroadcastChannel。
- 将状态切换为可操作的错误状态，显示“重新加入”入口。
- 补充连接失败后重新加入并重新建立连接的 fake WebRTC 回归测试。

## 验收标准

- [x] `disconnected`/`failed` 不再保留可复用的旧 peer。
- [x] 异常状态清理旧信令，避免旧 offer/answer 阻塞新协商。
- [x] 用户可以通过重新加入创建新媒体流和新连接。
- [x] 远端收到离开通知后回到等待状态。
- [x] test、typecheck、lint、build 和 diff 检查通过。

## 风险与边界

本地实验仍只支持同源窗口和手动重新加入；没有生产级 ICE 重连、服务端信令、鉴权或跨网络恢复策略。
