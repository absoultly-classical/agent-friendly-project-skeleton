## 目标

把“每完成一个功能提交一次 Git”和“每次提交前完成完整测试、交付前全部测试通过”
两条纪律写入项目文档，让后续 Agent 仅靠仓库内容就能遵循相同的提交粒度和验证
门槛，改动可追踪、可回滚。

## 范围

### 包含

- 在 `AGENTS.md` 新增“提交与测试”章节，明确提交粒度、提交说明、测试门槛。
- 在 `docs/development.md` 补充提交粒度说明，并把两条纪律并入改动检查清单。

### 不包含

- 不改动 `web/` 代码与测试实现。
- 不新增 CI、Git hook 或其他自动化强制手段。

## 必读上下文

- `AGENTS.md`
- `docs/development.md`
- `web/package.json`

## 约束与假设

- 约束：文档中引用的命令必须与当前 `web/package.json` 脚本一致
  （`lint`、`test`、`typecheck`、`build`、`check`）。
- 约束：新规则不得与既有“优先执行与改动最相关的验证”约定产生歧义，因此明确
  交付前需保证全部测试通过。
- 假设：仓库当前无 CI，纪律依赖 Agent 自觉执行与任务文档留证。
