# 0078：本地分享引用可识别化

- 状态：已完成
- 负责人：Codex

- 更新日期：2026-08-29
- 关联需求：REQ-010、REQ-020
- 关联任务：0029、0077

## 目标

让报告和回放分享结果在当前本地原型内可被重新打开，消除复制不存在的
`/reports/...`、`/replays/...` 路径所产生的服务端资源错觉。

## 范围

### 包含

- 使用应用根页面的 `?share=report|replay` 查询参数生成本地分享引用。
- 打开报告引用时恢复标题、会议模式和经过校验的当前本地会话快照。
- 打开回放引用时定位本地演示目录中的对应回放查看器。
- 对缺少标题、未知回放和无效快照提供安全回退，不读取或创建服务端资源。
- 更新架构说明并补充 jsdom 回归测试。

### 不包含

- 不创建真实报告 URL、媒体文件、分享权限或服务端存储。
- 不把本地快照当作跨用户权限凭据；链接内容仅用于当前前端原型演示。

## 验收标准

- [x] 报告和回放复制动作不再生成不存在的资源路径。
- [x] 报告分享引用可以恢复报告标题和课程/普通会议语义。
- [x] 当前报告快照可以通过本地引用恢复；无效快照回退到演示报告。
- [x] 回放分享引用可以自动打开对应的本地回放查看器。
- [x] test、typecheck、lint、build 和 diff 检查通过。

## 工作记录

- 2026-08-29：改用根页面查询参数生成本地引用；报告快照序列化到引用前先在打开时做字段校验，回放引用按本地演示目录定位。
- 2026-08-29：新增报告/回放深链接回归测试，并将分享成功/失败提示改为“本地引用”语义。

## 风险与边界

URL 中的报告快照是可见的本地演示数据，不是安全凭据，也不代表报告已上传或对外授权。
真实跨设备分享仍需要服务端报告资源、媒体存储、鉴权和权限模型。
