# 开发指南

> 确定技术栈后，请让 Agent 把占位说明替换成项目真实、可复现的开发方式。

## 开发环境

说明项目需要的运行时、依赖管理方式、数据库、中间件和本地服务。不要记录密钥或
只在某个人电脑上成立的路径。

## 初始化项目

写明 Agent 应如何准备一个全新的开发环境，包括配置样例、依赖安装和初始数据。

## 本地运行

说明启动入口、必要服务、默认地址，以及如何判断系统已经可以正常工作。

## 验证方式

列出格式检查、静态检查、单元测试、集成测试、构建验证和必要的人工验收方式。
所有说明都应让新 Agent 能直接执行，不需要从聊天中寻找补充参数。

## 如何选择测试范围

说明如何验证单个行为、单个模块、受影响范围和完整系统。Agent 工作中优先使用最小
相关验证，提交结果前再执行项目要求的更完整检查。

## 代码约定

- 让领域规则和依赖边界在代码结构中保持清晰。
- 公共接口、需求、测试和文档必须同步变化。
- 引入依赖或跨越组件边界前，先核对架构文档和已采纳决策。
- 生成文件要写明来源和更新方式，不应直接手工修改。

## 每次改动的检查清单

1. 当前任务已链接相关需求和决策编号。
2. 预期实现符合架构边界和依赖方向。
3. 已增加或更新能够证明对外行为的测试或验收证据。
4. 已执行相关验证，并把具体方式和结果写入任务文档。
5. 受影响的长期文档和任务交接均已更新。
