# 开发指南

## 项目结构

- `web/`：学习通会议 Web 原型。
- `docs/`：产品、架构、任务和长期决策。

## 开发环境

Web 原型使用 React、TypeScript、Vinext 和 Tailwind CSS。依赖清单与具体运行方式以
`web/package.json` 为准，Agent 应在 `web/` 目录完成开发与验证。

## 本地运行

Agent 启动开发环境后，应先确认首页能够正常响应，再向用户打开预览。用户不需要
执行命令或维护本地环境。

## 验证方式

- 自动化回归：`web/package.json` 的 `test` 脚本在 jsdom 中使用可控模拟对象验证本地
  WebRTC 状态机和会议页面关键流程，不需要真实浏览器、摄像头、麦克风或人工授权。
- 代码规范：`lint` 脚本执行 ESLint 全量检查，提交 Web 改动前应确保通过。
- 完整检查：`check` 脚本依次执行自动化测试、TypeScript 类型检查和生产构建；Agent
  在交付涉及 Web 代码的改动前应运行该脚本。
- 构建验证：生产构建能够成功产出部署文件。
- 交互验证：首页、创建会议、会中控制台、教学互动和课后报告均可进入。
- 响应式验证：桌面和手机宽度下不存在阻塞主要操作的溢出或遮挡；窄屏会中底部控制区保留全部核心操作，空间不足时只在控制组内部横向滚动，结束会议按钮保持可达；长会议标题在顶部收缩显示。
- 可访问性验证：交互元素具有清晰名称，键盘焦点可见，状态不只依赖颜色表达。

## 每次改动的检查清单

1. 当前任务已链接相关需求和决策编号。
2. 预期实现符合架构边界和依赖方向。
3. 主要用户流程有明确的交互反馈。
4. 已运行 lint 和完整检查脚本，并记录自动化测试、类型检查和生产构建结果。
5. 产品文档、任务交接和实际界面彼此一致。
