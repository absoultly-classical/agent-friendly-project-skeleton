# ADR-0001：项目文档是 Agent 的长期上下文

- 状态：已采纳
- 日期：2026-08-28
- 负责人：项目维护者
- 关联内容：`AGENTS.md`、`docs/README.md`

## 背景

新 Agent 进入项目时，可能看不到以前的聊天、终端历史或其他 Agent 的记忆。如果
目标、约束、验证方式和工作进度只存在于这些地方，任务就无法可靠恢复，重要理由也
不能和代码一起接受审查。

## 备选方案

### 以聊天历史作为主要上下文

单次会话内比较方便，但聊天不可稳定复用、难以版本管理，也不保证未来 Agent 能看到。

### 把长期上下文保存在项目中

需要持续维护文档，但信息可以搜索、审查、追溯，并通过同一套项目工作流提供给人和
Agent。

## 最终决定

项目仓库是 Agent 长期上下文的事实来源。`AGENTS.md` 提供简短的首次阅读路径；产品、
架构、开发和运维文档保存长期知识；任务文档保存可恢复的工作状态。聊天可以用于
即时协作，但不能成为后续工作所需事实的唯一存放处。

## 影响

- 代码变化导致项目文档过时时，该项工作不算完成。
- 暂停或交接任务时，必须留下验证证据和明确下一步。
- 文档通过链接和稳定编号减少重复，控制 Agent 需要读取的上下文量。
- 文档是否足够清晰，由“新 Agent 能否不看聊天直接接手”这一标准持续检查。
